# Презентации портала МЗ РК

Слайды увидят министр и руководство. Каждый слайд должен читаться за 5 секунд с дальнего конца
зала, выглядеть как часть продукта (палитра портала, герб, Inter) и не содержать ни одного слова,
которого не было в исходнике.

## 1. Жёсткие правила (уже были ошибки)

1. **Текст — только из исходника, дословно.** Тексты утверждены. Ничего не добавлять: ни
   слоганов, ни выводов, ни цифр, ни «итоговых» слайдов. Ничего не переписывать. Если хочется
   перестроить фразу (вынести «20 филиалов» крупной цифрой), это допустимо только как
   оформление тех же слов. Об этом сказать пользователю в отчёте.
2. **Столько же слайдов, сколько в исходнике** (13.11: из 3 слайдов сделали 7 — пришлось
   переделывать). Делить или объединять — только по просьбе.
3. **Прошлые варианты не трогать.** Новый вариант = новые файлы со следующей буквой (A, B, C →
   D, E). Правку («герб без острых углов») вносить только туда, куда просили.
4. **Герб** — `assets/emblem.png`: прозрачный фон, круглый, без белых углов и торчащих краёв.
5. **Светлый вариант по умолчанию**, если не сказано иное. Тёмный — отдельным вариантом.
6. **Форматы:** PDF по умолчанию. PNG 4K — рядом. PPTX — только **редактируемый** (живой
   текст и фигуры): PPTX-картинка аналитику не нужна. Если делать редактируемый PPTX не
   просили, его не делать и сказать, что можно.
7. Иконки — RemixIcon, без эмодзи. Шрифт Inter. Цвета — палитра портала (`assets/slide.css`).

## 2. Процесс

1. **Разобрать исходник.** Текст `.pptx` — `node .claude/skills/portal-deck/scripts/text-coverage.cjs "<исходник.pptx>" "<исходник.pptx>" "<scratchpad>/pptx/node_modules"`
   (печатает фразы и число слайдов) или скилл `anthropic-skills:pptx` для картинок и заметок.
   Посмотреть референс аналитика, если он есть: это обычно «нейрослоп», брать только смысл.
2. **Понять сообщение.** Одна мысль на слайд: что министр должен понять или решить. Определить
   иерархию: заголовок → 2–4 опорных блока → детали.
3. **Концепции.** Для вариантов — разные идеи композиции, а не перекраска одной (см.
   [references/design.md](references/design.md), раздел «Композиции»). Каждую идею назвать одним
   словом: «Архитектура», «Продукт», «Поток», «Платформа», «Хаб».
4. **Вёрстка — HTML 1920×1080.** Папка `exports/<презентация>/src/`. Скопировать туда
   `assets/slide.css`, `assets/wires.js` (линии-связи между блоками по реальной раскладке),
   `assets/emblem.png`. Корень слайда — `.slide`. Когда всё отрисовано —
   `document.body.dataset.ready = 1`.
5. **Рендер и проверка:** `node .claude/skills/portal-deck/scripts/render.mjs "exports/<презентация>" [--deck]` →
   PNG 4K + PDF. Скрипт сам ищет элементы за холстом, переполнение, текст мельче 18 px,
   не загрузившиеся иконки и картинки. Всё исправить.
6. **Сверка текста:** `text-coverage.cjs "<исходник>" "exports/<презентация>/src/<слайд>.html|…" "<nm>"` —
   «потеряно 0, добавлено 0». Осознанные перестройки фраз перечислить пользователю.
7. **Глазами** открыть каждый PNG (Read). Проверить: читается ли за 5 секунд, есть ли один
   главный акцент, ровная ли сетка, не мелко ли.
8. **Редактируемый PPTX** (если нужен):
   ```bash
   npm install --prefix "<scratchpad>/pptx" pptxgenjs@3.12.0
   node .claude/skills/portal-deck/scripts/html-to-pptx.cjs "exports/<п>/src/<слайд>.html" "exports/<п>/<слайд>.pptx" "<scratchpad>/pptx/node_modules"
   powershell -ExecutionPolicy Bypass -File .claude/skills/portal-deck/scripts/pptx-preview.ps1 -Pptx "<файл.pptx>" -Out "<scratchpad>/prev"
   ```
   Текст, плашки, разделители — нативные и редактируемые. Иконки, герб, скриншоты — отдельными
   картинками. Градиенты, свечения и декор — фоновой картинкой. Разметкой можно управлять:
   `data-pptx="bg" | "pic" | "skip"`. Превью из настоящего PowerPoint сравнить с PNG
   и исправить расхождения: перенос строк, ширины. Затем ещё раз `text-coverage` по `.pptx`.
9. **Живая версия (по желанию).** Если пользователь хочет показывать по ссылке, использовать
   тип артефакта Slides (`Artifact` → `quickstart`, intent `slides`).
10. **Отдать:** `SendUserFile` с PDF (и PPTX, если делали). В ответе — таблица вариантов: идея →
    когда брать. Плюс одна строка проверки: `Проверка: слайдов N = исходник · фраз M из M,
    добавлено 0 · render без замечаний · PPTX сверен в PowerPoint`.

## 3. Уровень — что отличает сильную презентацию

Коротко (подробно — [references/design.md](references/design.md)):
- **Иерархия с одного взгляда:** заголовок 54–64 px, опорный текст ≥ 24 px, подписи ≥ 18 px
  (на холсте 1920). Три уровня, не больше.
- **Сетка и воздух:** поля 72 px, единые отступы, всё выровнено по общим линиям.
- **Один акцент на слайд:** крупная цифра, живой скриншот портала или центральный узел схемы.
  Остальное тише.
- **Смысл через структуру:** связи, ярусы, поток слева направо вместо девяти одинаковых карточек.
- **Продукт вместо абстракций:** настоящий скриншот главной портала в рамке браузера сильнее
  любой иллюстрации.
- **Без AI-слопа:** без сетки «иконка + заголовок + описание» на всё, градиентных клякс, 3D-стока,
  эмодзи, «карточки в карточке», придуманных цифр и слайда «Спасибо за внимание», если его не было.
