# Каталог дефектов — что уже ловили аналитики и пользователь

Каждая запись: **что было** → почему → как не допустить → как проверить. Ключ аудита указан,
если дефект ловит `scripts/ux-audit.js`. Новые записи добавлять в конец своей группы с датой.

## А. Содержание: лишнее, дубли, не по постановке

**А1. Лишние разделы и поля сверх постановки** (09.10.2026, ЛМК). Аналитик прислала макет и
зачеркнула «Паспорт здоровья», «Историю приёмов», «Результаты», «Страхование ОСМС»: «у вас
в прототипе есть лишнее». Причина: «дополнял для полноты». → Состав экрана = состав постановки
и макета. Идея сверх ТЗ уходит в отчёт вопросом, а не в интерфейс. Проверка: каждый блок
страницы найти в чек-листе ТЗ; не нашёлся — убрать.

**А2. Поясняющий текст и визуальный шум** (19.10 главная, 23.10 и далее — почти в каждой
постановке). Эйлбраузы, абзацы под заголовками, описания под карточками, «строка доверия»,
подписи-инструкции. Владелец продукта: «из-за текста теряется суть портала». → Правило 4.
Проверка: прочитать страницу сверху вниз и про каждую строку спросить: «это данные, действие,
ошибка или статус?» Если нет — убрать или перенести в `data-tip`. Ключ аудита `proseHint`.

**А3. Дубли данных** (23.10, ЕД). «Назначено на» + плашка «Сейчас у сотрудника»; кнопка
«Назначить ответственного» в шапке + та же кнопка в плашке; маршрут согласования в решении
и в «Хронологии»; счёт 20 % в двух блоках; чипы срока под заголовком паспорта + те же данные
в «Информации об услуге»; название услуги подзаголовком мастера + в поле «Тип услуги». → Одно
значение — одно место. Ключ аудита `dupText` (эвристика: одинаковые строки на странице).

**А4. «Переписал таблицу полей из постановки»** (08.10, ЛМК). Первая версия была плоским списком
полей, как в ТЗ. Пользователь: «ты просто скопировал из постановки, сделай намного красивее».
→ Композиция: сводка сверху, группы, две колонки, состояния. Проверка: экран не должен читаться
как таблица из Word.

**А5. Бейджи с цифрами без смысла** (28.10, госуслуги бизнеса). Счётчики у пунктов списка
услуг — убрали. → Число показывать, только если оно помогает принять решение (непрочитанные,
просроченные).

**А6. Ссылки в чужую зону** (13.11, дашборд мониторинга). Карточки мониторинга вели
в администрирование, куда у руководителя нет доступа. → У информационных экранов нет переходов
туда, куда у роли нет прав.

**А7. Не та роль** (13.10, ЭПЗ). Сделали для гражданина то, что было для кабинета врача.
→ Роль определить на старте (`portal-task`, шаг 3). Постановка про ЭПЗ без явной роли относится
к врачу.

## Б. Сетка, ширина, адаптация

**Б1. Пустые поля по бокам** (07.10 профиль врача, 27.10 ЭПЗ, 15.09 кабинет бизнеса). На
ноутбуке лишние отступы, на 24–27″ блоки не растягиваются. → Никакого `max-width` у корня
раздела, ровный небольшой отступ, блоки растягиваются по ширине. Ключ аудита `gutters`.
Проверка на 1920 и 2560.

**Б2. Горизонтальная прокрутка таблицы на широком экране** (27.10, ЭПЗ «Заболевания»). → Колонки
по содержимому, длинные — `flex` с переносом. Широкий журнал — закреплённая колонка действий.
Ключ аудита `hScroll`.

**Б3. Сайдбар не на всю высоту** (15.09). → `min-height: 100vh` / `align-self: stretch`
у колонки навигации; проверять на короткой странице.

**Б4. Длинный сайдбар с прокруткой и длинными названиями услуг** (29.10, меню кабинета бизнеса).
«Лицензирование и аккредитация» раскрывалось на 10 услуг. → В сайдбаре только разделы
(«Фармацевтика», «Лицензирование и аккредитация»), а услуги показываются на странице справа.

**Б5. Шапка переполнена на ноутбуке** (08.11 «Инструкции», 03.11 «Отчётные формы»). Новые пункты
просили в шапку, а места на 1366–1440 нет. → Не втискивать: компактный пункт с панелью
(как «Инструкции» в `PortalHeader`), иконка с tooltip или меню. Проверка: шапка на 1366 без
переносов и наложений (замерить `scrollWidth`).

**Б6. Пустые обёртки дают лишнюю высоту** (23.10). `flex-basis` в колоночной раскладке растягивает
пустой блок. → Пустые контейнеры не рендерить (`sc-if`). Проверка: отступы до и после блока
одинаковые.

## В. Мелкий брак вёрстки

**В1. Бейдж с длинным текстом: текст вылезает, нет отступов** (16.10, АРМ ННЦРЗ / ФК). → Бейдж
«по содержимому»: `display:inline-flex`, `padding: 2px 8px`, `white-space: nowrap` или аккуратный
перенос с `line-height`. Ключ аудита `textSpill`.

**В2. Не видно выбранной вкладки; лишний вертикальный скроллбар в конце вкладок** (16.10). →
Активная вкладка — цвет + подчёркивание или подложка. У ленты вкладок `overflow` только по X
и скрытый скроллбар. Ключ аудита `hScroll`.

**В3. Поля фильтра на разной высоте** (16.10, «Прочие услуги»). Подписи разной длины переносятся.
→ Подписи в одну строку, у полей одинаковая высота. Ширина поля — по смыслу (у наименования
шире). Ключ аудита `misaligned`.

**В4. Выпадающий список уходит под блок ниже** (19.10, поиск на главной). → У открытого списка
`z-index` выше соседей, у предков нет `overflow:hidden`, при необходимости — `position: fixed`.
Проверка: открыть каждый список, особенно над следующим блоком страницы (сниппет
в final-check.md).

**В5. Обводка плашки с таблицей рвётся по краям** (03.11, «Отчётные формы»). Обводка была
`box-shadow: inset`, а фон `th` и `tr:hover` рисуется поверх неё. Пользователь просил запомнить.
→ Если внутри плашки до края доходит фон (шапка таблицы, ховер строки, подвал), обводка —
`border: 1px solid var(--n200)`, а скругление держит `overflow: hidden` у плашки. Ключ аудита
`insetStroke`. Проверять края в покое и при наведении на строку.

**В6. Нет ховера или фокуса у кликабельного** (23.10). → У каждой кнопки, ссылки, строки и
карточки со ссылкой есть `:hover` и `:focus-visible`. Проверка: навести на каждый тип элемента.

**В7. Неправильная заливка иконки в активном пункте меню** (08.10, «Медицинская книжка»). →
В активном состоянии брать `ri-*-fill` той же иконки, цвет — токеном. Проверка: открыть каждый
пункт меню.

**В8. Список без границ — «каша»** (29.10, услуги кабинета бизнеса). → Строки с разделителем
`--n200` или карточки с тонкой обводкой, ховер строки.

**В9. Окно со смешанными категориями** (28.10, услуги ЛС и МИ). → Сегментированный
переключатель над списком.

**В10. Двухстрочная запись реестра «сливается» с соседними** (23.11, «Центр уведомлений»).
Текст второй строкой голым абзацем + «зебра» + жирный текст — записи не читаются по отдельности.
→ Вторая строка — в подложке (непрочитанное — `--primary-lighter` с полосой слева, прочитанное —
светлая с обводкой `--n200`), без «зебры», между записями воздух и линия, текст в подложке —
по вертикали первого содержательного столбца. Проверка: на 1366 каждая запись читается как
отдельный блок, номера стоят ровно, на 1920 нет «хвостов» из 2–3 слов.

## Г. Прототип и данные

**Г1. Тестовый пользователь «не зарегистрирован»** (23.10, НЦЭЛС). При выборе сертификата
просили пройти регистрацию заново. → Демо-учётки для показа засеяны заранее (`mp-users` в
`EcpPicker`). У каждой роли, которую надо проверить, есть вход в один клик.

**Г2. Самодельная копия внешней системы** (21.10, Halyk). Окно «Оплата по QR-коду» убрали:
переход в банк сделают разработчики. → «Перейти к оплате» сразу меняет состояние.

**Г3. Выгрузка откатила несмёрженную работу** (14.10, госуслуги снова в окне). → Перед задачей
и выгрузкой проверять открытые PR (`portal-task`, шаг 0). Выгрузку собирать из ветки, в которой
есть вся работа.

**Г4. Старая выгрузка у коллег** (повторялось). → Выгрузка пересобирается после каждой правки
и проверяется `export-check.mjs`. В строке проверки указывается её время.
