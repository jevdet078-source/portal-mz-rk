# Финальная проверка — протокол

Цель — до отчёта найти и исправить всё, к чему придерётся аналитик или руководитель. Скриншоты
здесь нужны для собственной проверки, пользователю их не отправлять, если он не просил.

## 0. Поднять и открыть

- `mcp__Claude_Browser__preview_start({ name: "prototypes" })`. Порт берётся из результата: если
  5173 занят другой сессией, будет 5174 и т. д.
- Страница: `http://localhost:<порт>/project/<Имя страницы>.dc.html` (+ `?query`, `#hash`).
- Перед проверкой сбросить демо-данные страницы (панель «Прототип» → «Сбросить данные»), чтобы
  проверять то же, что увидит аналитик.
- Кабинет с входом: пройти «Вход» → ЭЦП-заглушка (`EcpPicker`) → нужный профиль. Пароль
  тестовых ключей — 1.

## 1. Сверка с ТЗ

Пройти чек-лист пунктов (`docs/tz/…` или план задачи). По каждому пункту: где сделано, видно ли
без скрытых условий, совпадают ли названия полей, статусов, кнопок и ошибок с ТЗ дословно.
Не сделано или сделано иначе — доделать или явно вынести в отчёт с причиной.
Обратная сверка: всё, что есть на экране, найти в ТЗ. Не нашлось — убрать (дефект А1).

## 2. Консоль

`read_console_messages({ onlyErrors: true })` на свежей загрузке каждой изменённой страницы:
ошибок нет. Ошибка шаблона `{{ … }}` или «is not defined» в `renderVals` означает, что страница
сломана частично. Если правили общий компонент, открыть 2–3 страницы, где он подключён.

## 3. Автоаудит

Каждое изменённое состояние: страница, каждое окно, раскрытый блок, пустое состояние, ошибка
сервиса, самые длинные данные. Размеры через `resize_window`, в конце — `preset: "desktop"`:

| Размер | Зачем |
|---|---|
| **1440×900** | основной: ноутбук 14–15″ |
| **1366×768** | маленький ноутбук: всё помещается, окна без прокрутки |
| **1920×1080** | монитор 24″: растягивается, нет пустых боков |
| **2560×1440** | монитор 27″: то же, строки текста не тянутся бесконечно |
| 768 / 375 | только переполнение: `hScroll` страницы = 0, ничего не обрезано |

```js
(0, eval)(await (await fetch('/.claude/skills/portal-ux/scripts/ux-audit.js', {cache:'no-store'})).text())
```

Разобрать каждую находку: настоящий дефект — исправить, ложное срабатывание — пропустить.
Обязательно смотреть ключи `cellOverflow`, `textSpill`, `boxOverflow`, `edgePad`, `misaligned`,
`gutters` (на 1920 и 2560), `hScroll`, `modalScroll`, `insetStroke`, `dupText`, `proseHint`.
`noHover` проверить наведением: ховер на JS скрипт не видит. `lowContrast` на `--n400`
(`#868C98`) — вторичному тексту дать `--text-sub-600`, а `--n400` оставить плейсхолдерам
и неактивному.

**Выпадающие списки — каждый.** Открыть и проверить, что список не обрезан предком и не уходит
под соседний блок (дефект В4):
```js
(() => [...document.querySelectorAll('[role=listbox],[role=menu],[class*=drop],[class*=menu],[class*=sugg]')]
  .filter((p) => p.getBoundingClientRect().height > 40 && getComputedStyle(p).visibility !== 'hidden').map((p) => {
    const r = p.getBoundingClientRect(); const cut = []; let a = p.parentElement;
    while (a && a !== document.body) { const cs = getComputedStyle(a);
      if (cs.overflowY !== 'visible' || cs.overflowX !== 'visible') { const q = a.getBoundingClientRect(); if (r.bottom > q.bottom + 1 || r.top < q.top - 1) cut.push(a.className || a.tagName); }
      a = a.parentElement; }
    const x = Math.min(innerWidth - 2, r.left + r.width / 2), y = Math.min(innerHeight - 2, r.bottom - 8);
    const top = document.elementFromPoint(x, y);
    return { el: (p.className || p.tagName).toString().slice(0, 40), inView: r.bottom <= innerHeight, cut, coveredBy: p.contains(top) ? null : (top && (top.className || top.tagName)).toString().slice(0, 40) }; }))()
```
`cut` не пустой, `coveredBy` не `null` или `inView: false` — дефект.

**Таблицы всего раздела, не только новой:** обойти вкладки, проверить `edgePad`, края плашки
в покое и при наведении на строку (дефект В5).

## 4. Глазами

Скриншоты на 1440 и 1920 (`computer screenshot`). Смотреть как придирчивый аналитик:
- ровные края, одинаковые отступы сверху и снизу у соседних блоков, поля и подписи на одной
  линии, ничего не вылезает;
- нет пустот, лишнего воздуха, пустых боков; нет лишнего текста и дублей значений;
- выбранная вкладка и активный пункт меню видны сразу, иконка активного пункта залита
  правильно (`-fill`);
- каркас такой же, как у соседних разделов (шапка, навигация, реестр, паспорт);
- длинные значения: ФИО, наименование услуги, организации, статус — подставить самое длинное из
  демо-данных;
- ховер и фокус у каждого типа кликабельного элемента (навести мышью).

## 5. Сценарий

Пройти основной сценарий постановки от начала до конца так, как пройдёт аналитик:
создать → заполнить → подписать / отправить → увидеть в реестре → открыть → изменить статус
другой ролью. Переключить в панели «Прототип» каждое состояние сервиса. Esc, Enter и клик мимо
у окон и списков. Кнопка не висит мёртвой: каждое действие что-то меняет.

## 6. Независимый взгляд (средняя и большая задача)

Свежий взгляд ловит то, к чему автор привык. Запустить субагента (Agent, `general-purpose`)
с брифом: пути к 3–6 скриншотам на 1440 и 1920 (сохранить их в scratchpad), путь к чек-листу
ТЗ, ссылка на `portal-ux/SKILL.md` (правила и «не AI-слоп») и `references/defects.md`.
Задача субагента — найти до 10 самых заметных проблем по приоритету, с координатами на
скриншоте. Свои выводы ему не передавать. Его находки проверить и исправить настоящие.

## 7. Итог

Только после шагов 1–6 написать строку проверки (`portal-finish`, раздел 5) и закрывать задачу.
Чего не проверял — так и написать.
