## Решения по UX

- Дневник — отдельный компонент `EpzDiary.dc.html` (бывшая страница, история git сохранена): `EpzView` и так 175 КБ, а правило проекта — крупное выносить.
- Вкладка только у гражданина: в кабинете врача (`EpzView mode="doctor"`) её нет, постановка — про ЭПЗ гражданина.
- Кнопка добавления — в шапке раздела справа, как «Экспорт отчёта» в других разделах ЭПЗ: не прыгает ряд вкладок, не нужна лишняя строка над карточками. Под заголовком на этой вкладке — описание дневника из первой постановки вместо «Источник: ЕХМД · режим просмотра» (гражданин здесь вносит данные сам).
- Дневник ведётся по пациенту, а не по случаю учёта: на его вкладке карточки случаев не выделены; клик по случаю возвращает к его «Постановке».
- Вкладки раздела — одной лентой: на планшете и телефоне прокручиваются, активная вкладка сама встаёт в видимую область.
- Вкладка в адресе: обновление страницы и возврат из другого раздела ЭПЗ открывают дневник снова.
- Не взяты из референса: синяя точка у вкладки, сводка «Крайний осмотр / Плановый визит / Динамика веса / Соблюдение диеты» и «Журнал записей самонаблюдения и отметок врача» — в постановке их нет.

## Вопросы аналитику и ответы (19.11.2026)

1. Случаи K29.0 / C50.4 не связаны с направлениями дневника — заменить на E11 / I10 / I50? **Ответ: да, дневник наблюдения должен зависеть от диагнозов.**
2. Нужна ли вкладка (только просмотр) в ЭПЗ пациента у врача? **Ответ: да, нужна.**
