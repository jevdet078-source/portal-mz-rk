# Карта страниц

20 файлов `.dc.html` в `project/`: 17 страниц + 3 общих компонента.
Все страницы, кроме «Вход» и «Кабинет врача», собираются по схеме
`Header → контент → Footer → Assistant`.

## Общие компоненты

| Файл | Размер | Что делает |
|---|---|---|
| `Header.dc.html` | 7.6 КБ | Герб + название МЗ, переключатель ролей (Гражданам / Бизнесу / Медперсоналу), язык ҚАЗ/РУС/ENG, кнопка «Войти». Проп `variant="account"` прячет роли и логин, показывает «На главную». Роль хранится в `localStorage['mp-role']` и рассылается событием `mp-role-change`. В кабинете бизнеса (`variant="account"` + `org`) чип организации — кнопка с меню: организация, БИН и переключатель роли **Заявитель / Администратор** (`localStorage['mp-biz-role']`, событие `mp-biz-role-change`). Активная роль всегда видна плашкой в чипе. |
| `Footer.dc.html` | 5.6 КБ | Подвал, 1440×360. |
| `Assistant.dc.html` | 11.9 КБ | Плавающая кнопка AI-помощника + чат. Подключается почти везде с `hint-size="1px,1px"`. |
| `BusinessNav.dc.html` | — | Меню кабинета бизнеса (272 / 80 px, сворачивается). Пропсы `active`, `collapsed="1"`. Пункты открываются по онбордингу из `localStorage['mp-biz-step']`. В роли администратора к ним добавляется группа «Администрирование» → «Пользователи», «Организации», «Рабочий календарь». |

`Header` в варианте `account` принимает также `org` и `bin` — плашка организации в кабинете бизнеса,
и `layout="app"` — шапка на всю ширину (слева 16px, справа 32px) для страниц кабинета с сайдбаром.
В варианте `account` вместе с `layout="app"` появляется колокольчик уведомлений: бейдж с числом непрочитанных, выпадающий
список последних трёх и «Посмотреть все» → `Уведомления.dc.html` (Figma 6406:104361).

`BusinessNav` подключается с `style="height:100%;"`: рантайм переносит высоту на обёртку `div.sc-host`,
без этого меню не растягивается на всю высоту колонки.

## Авторизация и кабинеты

| Страница | Файл | Состояние |
|---|---|---|
| **Вход** | `Вход.dc.html` | По постановке «Авторизация» и замечаниям аналитика: «Вход» → ЭЦП (проверки идут в фоне, на кнопке «Проверяем ЭЦП…») → профиль → пароль (логин = ИИН из ЭЦП, только чтение). Заголовок шага не меняется, ошибки — плашкой под ним: «Вы ещё не зарегистрированы» + переход в регистрацию с тем же ключом, «Учетная запись недоступна…», невалидная ЭЦП. Плашка о многофакторной аутентификации. Единственный профиль выбирается сам. Профили: Гражданин → `Личный кабинет`, Медперсонал → `Кабинет врача`, Бизнес → `Кабинет бизнеса` (или `?return=`), Госорган → главная. Пишет `mp-iin`, `mp-profile`, `mp-role`. |
| **Регистрация** | `Регистрация.dc.html` | По постановке «Регистрация» и замечаниям аналитика: «Регистрация» (4 шага кратко + плашка о многофакторной аутентификации) → ЭЦП → данные сертификата (владелец, ИИН, организация/БИН, срок, серийный номер) + согласие на обработку ПД → в фоне КГД / справочник `organization_go` / СУР → профиль (статус ИП / медорганизации — внутри карточки, недоступный профиль показан с причиной) → «Продолжить регистрацию» (ГБД ФЛ / ЮЛ в фоне) → пароль → «Регистрация завершена». ## Чего ещё нет (важно для планирования)

- **Кабинет бизнеса: заявления КНФ и раздел уведомлений** — ждут ссылок на Figma.
- **Регистрация цены: другие пути** — «Внесение изменений в цену», типы цены «Отечественного» и «Контрактного производства», заявления МИ «производимого в РК» и «in vitro» — не перенесены (в демо один путь на ЛС и один на МИ).
- **АРМ эксперта** (модерация заявок) — не спроектирован (переносим из Figma).
- **Кабинет госоргана** — заглушка.
- **Мобильные раскладки** — все прототипы под десктоп 1440, адаптива нет.
- **Состояния**: пустые списки, скелетоны загрузки, ошибки — почти нигде не заданы.
