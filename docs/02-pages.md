# Карта страниц

20 файлов `.dc.html` в `project/`: 17 страниц + 3 общих компонента.
Все страницы, кроме «Вход» и «Кабинет врача», собираются по схеме
`Header → контент → Footer → Assistant`.

## Общие компоненты

| Файл | Размер | Что делает |
|---|---|---|
| `Header.dc.html` | 7.6 КБ | Герб + название МЗ, переключатель ролей (Гражданам / Бизнесу / Медперсоналу), язык ҚАЗ/РУС/ENG, кнопка «Войти». Проп `variant="account"` прячет роли и логин, показывает «На главную». Роль хранится в `localStorage['mp-role']` и рассылается событием `mp-role-change`. В кабинете бизнеса (`variant="account"` + `org`) чип организации — кнопка с меню: организация, БИН и переключатель роли **Заявитель / Администратор** (`localStorage['mp-biz-role']`, событие `mp-biz-role-change`). Активная роль всегда видна плашкой в чипе. |
| `Footer.dc.html` | 5.6 КБ | Подвал, 1440×360. |
| `Assistant.dc.html` | 11.9 КБ | Плавающая кнопка AI-помощника + чат. Подключается почти везде с `hint-size="1px,1px"`. |
| `BusinessNav.dc.html` | — | Меню кабинета бизнеса (272 / 80 px, сворачивается). Пропсы `active`, `collapsed="1"`. Пункты открываются по онбордингу из `localStorage['mp-biz-step']`. В роли администратора к ним добавляется группа «Администрирование» → «Рабочий календарь». |

`Header` в варианте `account` принимает также `org` и `bin` — плашка организации в кабинете бизнеса,
и `layout="app"` — шапка на всю ширину (слева 16px, справа 32px) для страниц кабинета с сайдбаром.
В варианте `account` вместе с `layout="app"` появляется колокольчик уведомлений: бейдж с числом непрочитанных, выпадающий
список последних трёх и «Посмотреть все» → `Уведомления.dc.html` (Figma 6406:104361).

`BusinessNav` подключается с `style="height:100%;"`: рантайм переносит высоту на обёртку `div.sc-host`,
без этого меню не растягивается на всю высоту колонки.

## Авторизация и кабинеты

| Страница | Файл | Состояние |
|---|---|---|
| **Вход** | `Вход.dc.html` (14 КБ) | Два шага: `form` (ИИН+пароль / ЭЦП) → `role` (выбор профиля). Профили: Гражданин → `Личный кабинет`, Медперсонал → `Кабинет врача`, Бизнес → `Кабинет бизнеса` (или на страницу из `?return=`), **Госорган → тупик**. ИИН пишется в `localStorage['mp-iin']`, профиль — в `mp-profile`. |
| **Кабинет бизнеса** | `Кабинет бизнеса.dc.html` | Главная «Единого окна» внутри портала: онбординг «Три шага до подачи заявок» (договор → заявка на платёж → услуги), экран «Онбординг завершен», блок «Помощь» (документы / видео-инструкции). Перенесено из Figma 1:1, оболочка — портальная. |
| **Мои процессы** | `Мои процессы.dc.html` | Список сквозных процессов, табы ЛС / МИ (`#ls` / `#mi`), прогресс по этапам. |
| **Договора** | `Договора.dc.html` | Перечень договоров / Архив, «Перейти в договора» → выбор НЦЭЛС или ННЦРЗ. НЦЭЛС — внешняя система во iframe (растровые снимки с кликабельными зонами), ННЦРЗ — публичная оферта; принятие оферты открывает шаг 2 онбординга. |
| **Платежи** | `Платежи.dc.html` | Внешняя система «Экспертиза» во iframe: заявки на платеж → выбор формы → заполнение (снимки с кликабельными зонами). |
| **Услуги** | `Услуги.dc.html` | Реестр заявок ЛС / МИ: фильтры, родительские и дочерние заявки, меню действий, «Создать» → модалка «Выберите вид услуги» с подтипами. |
| **Паспорт регистрации цены** | `Паспорт регистрации цены.dc.html` | Паспорт услуги внутри кабинета, `#ls` / `#mi`: порядок, документы по вкладкам, результаты, основания для отказа. «Подать заявку» → лоадер → мастер. |
| **Заявка на регистрацию цены** | `Заявка на регистрацию цены.dc.html` | Мастер заявителя из 5 шагов (поля статичные), «Подписать и отправить» → ЭЦП → «Ожидание проверки» → «Экспертиза завершена». `#ls`, `#mi`, `#ls-result`, `#mi-result`. |
| **Заявление КНФ** | `Заявление КНФ.dc.html` | Мастер заявителя из 5 шагов (Данные услуги → Сведения о заявителе → Заявление → Досье → Загрузка документов), поля статичные. «Подписать и отправить» → ЭЦП → этапы «Проверка ННЦРЗ»: ожидание → платёжное поручение 20% → «Экспертиза завершена» (уведомление об автоматическом включении в КНФ). `#result` — отправленное заявление. |
| **Уведомления** | `Уведомления.dc.html` | Центр уведомлений кабинета: табы Все / Прочитанные / Непрочитанные, таблица решений по заявкам, пагинация, состояние «Технический сбой». Открывается из колокольчика в шапке. |
| **Процесс** | `Процесс.dc.html` | Страница сквозного процесса: ЛС — 5 этапов, МИ — 4. Таймлайн по этапам, оплата госпошлины с загрузкой чека и модалкой подтверждения, параллельные этапы 4–5. Этап переключается панелью прототипа. |
| **Рабочий календарь** | `Рабочий календарь.dc.html` | Администрирование кабинета бизнеса: производственный календарь для таймеров КНФ и ЕД. Три месяца (текущий + 2), клик/протяжка/Shift/Ctrl по сетке, массовый статус, стандартный график и госпраздники РК, счётчик рабочих дней, черновик с предупреждением при уходе, скелет загрузки, тост и сценарий ошибки сохранения. Доступна только в роли «Администратор». |
| **Личный кабинет** (физлицо) | `Личный кабинет.dc.html` (51 КБ) | 6 разделов: Обзор, Паспорт здоровья (ЭПЗ, аккордеоны), История приёмов, Результаты, Страхование ОСМС, Уведомления. Плюс проактивный сценарий по беременности и модалка записи на приём с тостом подтверждения. |
| **Кабинет врача** | `Кабинет врача.dc.html` (227 КБ) | Самый большой файл. Разделы: Главная (сводка), Амбулаторная помощь, Заболевания, Госпитализация, Профилактика (скрининги / прививки / патронаж), Измерения, Диспансерный учёт (постановка → наблюдение → выполнение стандарта → рецепты → снятие), Женское здоровье (беременность, анамнез, ЖФВ, контрацепция), Вызовы скорой, Больничные и справки. |

## Чего ещё нет (важно для планирования)

- **Кабинет бизнеса: заявления КНФ и раздел уведомлений** — ждут ссылок на Figma.
- **Регистрация цены: другие пути** — «Внесение изменений в цену», типы цены «Отечественного» и «Контрактного производства», заявления МИ «производимого в РК» и «in vitro» — не перенесены (в демо один путь на ЛС и один на МИ).
- **АРМ эксперта** (модерация заявок) — не спроектирован (переносим из Figma).
- **Кабинет госоргана** — заглушка.
- **Мобильные раскладки** — все прототипы под десктоп 1440, адаптива нет.
- **Состояния**: пустые списки, скелетоны загрузки, ошибки — почти нигде не заданы.
